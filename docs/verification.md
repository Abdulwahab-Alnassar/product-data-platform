# Verification record

Verification uses the sanitized public sample and synthetic test rows. It does
not use a private/full local dataset. Commands and environments are included so
the results can be reproduced rather than accepted on trust.

## Checks

- Python 3.12: `python -m pytest -v` on Linux and Windows in GitHub Actions.
- PostgreSQL 17: marked tests run in isolated temporary schemas against a disposable database.
- Full Compose build: database initialization, sample ETL, model training, API readiness, dashboard health.
- Live HTTP smoke: catalog, search, predictions, cited answers, monitoring, metrics.
- SQLite backup/restore: verified rows, revision metadata, and refusal to overwrite.
- PostgreSQL backup/restore: dump restored into a new database and checked in CI.
- UI: Streamlit AppTest drives analytics filters, prediction, search, Q&A, and health.
- Data contracts: invalid values, retries, conflicting IDs, out-of-order versions, concurrent writers,
  transaction rollback, read-only access, and deleted-product handling.
- Model: duplicate-name isolation, deterministic splits, unknown vocabulary, and JSON serving parity.

The public [Actions history](https://github.com/Abdulwahab-Alnassar/product-data-platform/actions)
is the authoritative record for the final commit. PostgreSQL tests are intentionally
skipped when TEST_DATABASE_URL is not configured locally; they run in the separate CI job.

## Reproducing the demo evaluation

```powershell
python -m src.demo
$env:SQLITE_PATH = 'data/processed/demo/products.db'
python -m src.evaluate_search
python -m src.monitor
```

`evaluation/demo/model_evaluation.json` and `search_evaluation.json` are committed
snapshots generated by these commands. The model has a 19-item test set and the
retrieval fixture has five manually selected queries. These are demonstration
measurements, not a production benchmark. No minimum performance threshold was
tuned against the test set to make the verification pass.

## Not exercised as external services

- An actual Ollama model: adapter success/failure and citation contracts are tested
  using controlled HTTP responses. Generated-answer accuracy is not claimed.
- A public deployment: the application is delivered for local/container execution.
- The full Kaggle dataset or live inventory: neither was available as a live source.
- High-concurrency production load or a streaming latency SLA.

Normal use does not need these external capabilities. Read the operations guide
before configuring them. Run the same checks after dependency or schema changes.
